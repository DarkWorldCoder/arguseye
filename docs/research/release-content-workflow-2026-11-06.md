# Release and feature communication

Maker request recorded 6 November 2026: prepare distinct LinkedIn, X, DEV, Medium and eligible daily.dev content for new Arguseye features/releases. This checklist does not itself create a scheduler or prove publication. It supplements the existing daily plan and exact-copy review records.

## Trigger and evidence

When a feature becomes public or a package release passes its gates, create one content pack under `launch/distribution/releases/<version-or-feature>/`. Group related commits into a useful lesson; do not turn every internal commit into a repetitive launch post.

Record the source commit/tag, exact public package versions per registry, test evidence, known limits, documentation URL and genuinely new reader takeaway. An npm upload receipt, a Git tag and a publicly installable package are separate states. Never describe a proposed feature as released.

Read the product documentation, latest publication receipts and native queues before drafting/scheduling. Use Content Engine and Repurpose to adapt one verified example; review with Humanizer and Social. Do not invent maker experiences or imply human-only authorship.

Earlier broad scheduling or account access does not resolve a new CAPTCHA, legal agreement or missing action-time approval. Keep that destination pending while continuing independent work. The daily cadence remains active; this checklist does not replace it or authorize extra same-day posts.

## Per-channel receipt

Store exact final copy, candidate hooks, selected opening/family, theme, core takeaway, format, visual asset identity, CTA, compared recent/scheduled items, novelty rationale and source evidence. Use statuses such as `draft`, `approved`, `scheduled`, `published_verified`, `ineligible` or `blocked`; keep a reason and the next required action.

After publication, verify the actual permalink and visible content; save a screenshot where available and reconcile `launch/distribution/status.json`. For scheduled posts, verify date/time in the native queue and record the reservation without claiming it is already published. Do not lose an existing composer draft or overwrite another agent's receipt.

A draft is complete preparation, not completed distribution. Report publication only after its destination-specific verification.
