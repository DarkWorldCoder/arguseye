Eyes for coding agents · React, Next.js, Vue

Your coding agent can see what it just built.

Arguseye renders any React, Next.js or Vue component from source, exactly as your app shows it, with the dev server off. Real props come from the places your code already uses the component; your theme, layouts and global CSS apply. The agent gets a cropped PNG, the accessibility tree, what changed since its last render, and errors with file paths, in one call that takes about 40 ms when warm.

$ npx arguseye install claude

Also codex, gemini, cursor, windsurf, vscode, antigravity, copilot or all. One command writes the MCP server and the skill where your agent reads them. Then tell the agent: look at the card you just changed.

The agent asks for a file and, optionally, a call site. Arguseye finds the real props, wraps the component in the app's providers and layouts, draws it in Chromium and answers with compact evidence.

The problem

Why an agent needs eyes

Coding agents write UI blind. They edit a component, read the code back, and declare it done. The button that wraps onto two lines, the card that lost its padding, the theme that never applied: none of that is visible in a diff. The usual remedy is to start the dev server, wait for it, navigate to the page, log in, click into the right state and take a screenshot. That is six to ten tool calls, it breaks whenever the app can't boot, and it only ever shows saved files.

Compared with Storybook you write no stories; compared with Preview.js the props are real and the layouts are yours; compared with browser-automation MCPs nothing has to be running. The numbers behind this are in benchmarks/.

What the agent gets back

Five tools. Each returns compact evidence: text and a cropped image, never a whole page.

render_component

PNG cropped to the component, accessibility tree, errors[], warnings[], timings, and changes since the previous render of the same target. usage takes the props of a real call site; in_context renders inside that call site's parent elements; frame is a stand-in parent box; actions and storage set the state first. Function props: {"$fn": "(x) => …"}.

{file, export?, usage?, props?, viewport?, in_context?, frame?, actions?, storage?}

list_usages

Every call site with its literal props, the props that depend on runtime values, and the JSX ancestors.

{file, export?}

render_usages

The component at every call site: the blast radius of a change in one call.

{file, export?, viewport?}

describe_props

The props schema from the TypeScript type, with sample values.

{file, export?}

render_diff

An explicit before/after against a captureId.

{baselineId}

CLI, for agents without MCP

shot, usages, serve (a live page with hot reload), diff and install.

npx arguseye shot src/Card.tsx --export Card --usage app/page.tsx:12 --in-context --out card.png

For people

The same renderer, beside your code

Open a .tsx, .jsx or .vue file and run Preview Component (the eye icon in the editor title, or Ctrl+Alt+P). The panel shows the component with the props from its first real usage, follows the file you edit, re-renders in under 50 ms as you type with component state kept, scales the preview to fit (or 1:1), and has a props form built from the component's type.

Extension id ayushniroula.arguseye on the Marketplace and Open VSX (Cursor, Windsurf, VSCodium).

Under the hood

How it stays exact and fast

  • Your toolchain, one buildYour files run through oxc one module at a time; your packages are pre-bundled once by Rolldown from your own node_modules in a worker process and cached by lockfile, so React, MUI and Tailwind are the versions your app uses. Next.js app-router projects run on Next's vendored React, like the app itself.
  • Your layouts and CSSRoot and nested layouts and templates wrap every render: global CSS, <html>/<body> classes, providers with their props, CssBaseline-style siblings. Tailwind v4 compiles with your theme, Tailwind v3 through your PostCSS config, plus Sass, CSS modules, public/ assets, image imports and NEXT_PUBLIC_* env.
  • Real pixelsnext/link, next/image and next/navigation render Next's markup; Chromium draws the pixels. The capture is a clip to the component's box with transitions ended and animations settled.
  • Hot swapsEdits are hot-swapped with React Fast Refresh, from the editor or from disk. A target's whole import graph is preloaded in one batch; barrel imports of icon packages are rewritten per member; lazy images load eagerly so the frame settles in milliseconds.

Measured on the 1,197-file app above: server ready in 2–11 s, first render 1.5 s, a full section 0.9 s, the same target again 0.3 s; the server stays around 500–750 MB. The technique is described in docs/technique.md.
